# Primal App — Описание поведения приложения

## Общая концепция

Primal App — мобильное приложение-компаньон для настольной кооперативной игры «Primal. Пробуждение». Приложение автоматизирует учёт здоровья монстра, накопленного урона, ярости, фаз боя и смены стоек.

**Платформа:** Kotlin Multiplatform (Android + iOS).

**Состояние приложения управляется конечным автоматом** из состояний `FightPhase`:
`PRE_BATTLE`, `SETUP`, `PHASE_I`…`PHASE_IX`, `VICTORY`, `DEFEAT`.

```
                    ┌─────────────┐
                    │  PRE_BATTLE │──── Начало боя ────┐
                    └─────────────┘                    │
                           ▲                           ▼
                           │                    ┌──────────┐
                           │                    │ PHASE_I  │
                           │                    └────┬─────┘
                           │               ┌─────────┼──────────┐
                           │               │  нанесён урон       │
                           │               ▼                     ▼
                           │        ┌──────────┐          ┌──────────┐
                           │        │ PHASE_II │          │  DEFEAT  │ ← раунды истекли
                           │        └────┬─────┘          └──────────┘
                           │    ┌────────┼────────┐
                           │    │ нанесён урон      │
                           │    ▼                   ▼
                           │ ┌──────────┐    ┌──────────┐
                           │ │PHASE_III │    │  DEFEAT  │
                           │ └────┬─────┘    └──────────┘
                           │      │ … (цепочка до PHASE_IX)
                           │      ▼
                           │ ┌──────────┐
                           └─│ VICTORY  │
                             └──────────┘
```

**Поток данных:** `Monster + Hunter (модели)` → `BattleViewModel (MVVM)` → `StateFlow<BattleScreenState>` → `MainActivity (Compose UI)`

## 2. Экран «Battle» — Боевой экран

**Файл:** `MainActivity.kt:158–306` — функция `BattleScreen`

Отображается при состояниях `PHASE_I`…`PHASE_IX`.

### 2.1 Информационная панель

В верхней части экрана:
- **Текущая фаза** (I…IX) и раунд (N / 10)
- **Здоровье монстра** и текущая **ярость**
- **Накопленный урон** и **прочность** (урон для раны)
- **Статус** (Устойчивость / Обычный) и **порог смены стойки**

### 2.2 Нанесение урона

Нанесение урона управляется конечным автоматом режимов ввода (`InputMode`):

```
                    нажатие (+N)
     ┌──── NONE ──────────────────► QUICK_BUTTON ─────┐
     │                                  │   таймер 2с  │
     │  OK / Cancel                клик в поле         │
     │                                  │   (сброс     │
     │                                  ▼   таймера)   │
     ├──────── MANUAL ◄─────────────────┘              │
     │            │                                    │
     │      нажатие (+N)                               │
     │      (накопление,                               │
     │       без таймера)                              │
     │            │                                    │
     └────────────┴── Enter / OK ──► commitDamage() ───┘
```

#### Режимы ввода (`InputMode`)

| Режим | Описание | Таймер |
|-------|----------|--------|
| `NONE` | Начальное состояние, нет активного ввода | Нет |
| `MANUAL` | Пользователь печатает в поле ввода | Нет |
| `QUICK_BUTTON` | Нажаты кнопки (+1/+5/+10/+50) | 2 секунды |

#### Кнопки быстрого добавления

| Кнопка | Значение | Метод ViewModel |
|--------|----------|-----------------|
| +1 | 1 | `onQuickButtonPress(1)` |
| +5 | 5 | `onQuickButtonPress(5)` |
| +10 | 10 | `onQuickButtonPress(10)` |
| +50 | 50 | `onQuickButtonPress(50)` |

**Поведение кнопок (+1/+5/+10/+50):**

1. **Если режим `NONE` или `QUICK_BUTTON`:** значение накапливается (`pendingDamage += amount`), таймер 2с запускается или сбрасывается. Поле ввода обновляется.
2. **Если режим `MANUAL` (пользователь уже печатал):** значение накапливается, но таймер **не запускается**. Поле ввода обновляется.
3. **Таймер 2 секунды:** если в течение 2 секунд не нажата ни одна кнопка, урон применяется автоматически (`commitDamage()`).
4. **Кнопка «Применить урон сейчас (N)»:** отображается при активном таймере для немедленного применения.

#### Ручной ввод урона

- **Поле ввода** (`OutlinedTextField`) управляется ViewModel через `state.damageInputText`.
- При вводе с клавиатуры режим переключается в `MANUAL`, таймер отменяется.
- **Клавиша Enter** на клавиатуре или кнопка **OK** — мгновенное применение урона.
- **Кнопка «Отмена»** — сброс `pendingDamage` в 0, очистка поля, возврат в `NONE`.

#### Лечение босса (отрицательный урон)

При вводе отрицательного значения в поле урона босс лечится. Реализовано в `MonsterExt.kt:69-99` — метод `healWound()`.

**Механика:**
1. Сначала гасится накопленный урон (`accumulatedDamage`).
2. Оставшееся исцеление делится на `damageForWound`: за каждые полные `damageForWound` единиц `currentHealth` увеличивается на 1 (заживление раны).
3. Остаток формирует новый `accumulatedDamage` для следующего порога.

**Пример:** монстр имеет `accumulatedDamage = 3`, `damageForWound = 4`, `currentHealth = 5`. Вводится `-9`:
- 3 единицы гасят `accumulatedDamage` → 0
- 6 единиц = 1 полная рана (4) + остаток 2 → `currentHealth = 6`, `accumulatedDamage = 2`

**Примечание по UI:** клавиатура `KeyboardType.Number` может не отображать знак минуса на некоторых устройствах. При необходимости заменить на `KeyboardType.Decimal` в `BattleScreen.kt:143`.

#### Смешанные сценарии

| Сценарий | Поведение |
|----------|-----------|
| Кнопки (+N) → клик в поле ввода | Таймер останавливается, урон только по OK/Enter |
| Ручной ввод → кнопки (+N) | Число меняется, таймер не запускается |
| После Отмена / OK | Возврат в `NONE`, таймер запустится при следующем (+N) |

#### Применение урона

**Файл:** `BattleViewModel.kt` — метод `commitDamage`

Вызывает `Monster.takeDamage(pendingDamage)`. Перед применением сохраняет снимок состояния монстра (`MonsterSnapshot`) для возможной отмены.

#### Отмена последнего действия

**Файл:** `BattleViewModel.kt` — метод `onUndoPress`

Кнопка **«Отменить действие»** отображается после каждого мутирующего действия (`canUndo = true`). Поддерживается **до 10 отмен** подряд. Восстанавливает полное состояние монстра (здоровье, фазу, накопленный урон, ярость) и `FightPhase` на момент перед последним действием.

**Действия, которые можно отменить:**
- Нанесение/лечение урона (`DAMAGE`)
- Изменение ярости через кнопки ±1, +1/охот, +1/охот-1 (`RAGE`)
- Смена стойки через диалог (`PHASE_CHANGE`)
- Завершение раунда (`ROUND_END`)

**Реализация:** стек `actionHistory: MutableList<ActionSnapshot>` (max 10). Снимок сохраняется перед каждым действием через `saveSnapshot()`. При отмене:
1. Извлекается последний `ActionSnapshot`
2. Восстанавливаются поля `Monster` (health, accumDamage, phase, rage, isDefeated)
3. Восстанавливается `FightPhase`
4. `canUndo = actionHistory.isNotEmpty()`

Алгоритм `Monster.takeDamage` (файл: `MonsterExt.kt:13–63`):
1. `accumulatedDamage += amount`
2. **Цикл ран:** пока `accumulatedDamage >= damageForWound`:
   - `accumulatedDamage -= damageForWound`
   - `currentHealth -= 1`
   - Если `currentHealth <= 0` → `isDefeated = true`, возврат
   - Если НЕ hardened И `currentHealth <= healthForStanceChange` И не последняя фаза → `currentPhase++`
3. **После цикла:** если hardened и были раны → `accumulatedDamage = 0` (остаток сгорает). Иначе остаток сохраняется

### 2.3 Управление яростью

**Файл:** `BattleViewModel.kt:159–199`

В начале боя монстр получает **ярость, равную числу охотников** (`startBattleWithHunters` → `rage = hunters.size`; задача 35.2).

| Кнопка | Метод | Поведение |
|--------|-------|-----------|
| -1 | `removeRage(1)` | `rage = max(rage - 1, 0)` |
| +1 | `addRage(1)` | `rage += 1` |
| +1/охот | `addRagePerHunter()` | `rage += hunterCount` |
| +1/охот-1 | `addRagePerHunterMinusOne()` | `rage += max(hunterCount - 1, 0)` |

### 2.4 Статус «Устойчивость»

**Файл:** `BattleViewModel.kt:201–210` — метод `toggleHardened`

- `Switch`-переключатель
- Вызывает `Monster.toggleHardened()` (файл: `MonsterExt.kt:85–88`)
- `isHardened = !isHardened`
- Влияет на `takeDamage`: при `isHardened = true` остаток урона после нанесения ран **сгорает** (обнуляется)

### 2.5 Всплеск ярости

**Файл:** `BattleViewModel.kt` — метод `confirmRageSurge`, поле `showRageSurgeDialog`

При каждом изменении ярости (кнопки +1/-1/+охот, завершение раунда, отмена действия) проверяется условие:
```
rage >= hunterCount * 3
```

При срабатывании:
- Отображается диалог **«Всплеск ярости»** с сообщением о критическом уровне
- Кнопка **OK** вызывает `confirmRageSurge()` — ярость сбрасывается до `hunterCount`

### 2.6 Выход в главное меню

Кнопка **«Выход в меню»** — доступна на боевом экране, экране победы и поражения:
- **QuickBattle:** вызывает `viewModel.resetBattle()` + `campaignViewModel.onBackToMenu()` — сброс боя и возврат в главное меню
- **CampaignBattle:** вызывает `campaignViewModel.onBackToMenu()` — возврат в главное меню

### 2.7 Завершение раунда

**Файл:** `BattleViewModel.kt` — метод `endRound`

Кнопка **«Закончить раунд»**:
1. Если есть накопленный, но не применённый урон (`pendingDamage > 0`):
   - Вызывает `Monster.takeDamage(pendingDamage)`, получает `DamageResult`
   - Если босс **побеждён** → `phase = VICTORY`, досрочный выход (раунд не завершается)
   - Если **смена стойки** (`result.phaseChanged`) → обновляется `FightPhase`, выставляется `showPhaseChangeDialog = true`
2. Вызывает `Monster.endRound(hunterCount)` — добавляет +1 ярости за каждого охотника
3. `currentRound += 1`
4. Если `currentRound > maxRounds (10)` → `phase = DEFEAT` (поражение)
5. Иначе продолжается текущая фаза, проверяется всплеск ярости

## 3. Смена стойки — диалог PhaseChangeDialog

**Файл:** `MainActivity.kt:308–352`

Отображается при `state.showPhaseChangeDialog == true` (модальное окно `AlertDialog`).

Три поля:
- **Урон для нанесения раны на игрока** — новый `damageForWound` (на игрока, умножается на `hunterCount`)
- **Здоровье для смены стойки** — новый порог. Если `> 0`, появляется третье поле. Если `0` или пусто — последняя стойка (дальнейшая смена не происходит).
- **Здоровье босса в новой стойке** — опционально, начальное HP для новой фазы

Кнопка **OK** вызывает `viewModel.confirmPhaseChange(wound, stance, bossHealth)`:
- `Monster.resetPhase(damageForWound, healthForStanceChange)` — обновляются пороги; `accumulatedDamage` переносится на новую стойку, обнуляется только если монстр устойчивый
- Если `bossHealth > 0`, устанавливается `currentHealth = bossHealth`
- Диалог закрывается. При следующем достижении порога смены стойки диалог появится снова — до 9 стоек.

Кнопка **Отмена** вызывает `viewModel.dismissPhaseChangeDialog()`:
- Откатывает урон, вызвавший смену стойки (через `onUndoPress()`)
- Восстанавливает состояние монстра к моменту перед уроном
- Закрывает диалог (`showPhaseChangeDialog = false`)

## 7. Режим кампании (v2 — реализовано)

- До **10 кампаний** с локальным хранением через Room (SQLite) в KMP-модуле shared
- Создание кампании: название + выбор классов охотников (6 классов)
- Лист кампании: охотники, навыки, ресурсы, заметки, глава
- **Древо навыков**: 5 ветвей (А–Д) × 2 ступени, tier 2 требует tier 1
- **Ресурсы**: 6 материй, 6 растений, 9 стихий — учёт, кнопки +/− (по 1, минимум 0). Рядом с каждым ресурсом отображается его иконка из `androidApp/src/main/res/drawable/` (файлы `scales.png`…`ice.png`, маппинг `Material/Plant/Element.iconRes()`; задача 35.3/35.4).
- **Продвижение**: переход к следующей главе (глава += 1) происходит при «Принять» наград главы после победы; ручной режим — кнопки на листе кампании
- **Кузня/лаборатория**: старт 1 → гл.4 → 2 → гл.8 → 3 (повышение при «Принять» наград главы с флагами `forgeUpgrade`/`labUpgrade`)
- **Пост-победный флоу**: трофей + завершение активного задания + выбор открывшихся заданий + ввод ресурсов (материи и растения, начисляются всем охотникам) + стихия босса
- **Награда за победу над боссом**: каждому охотнику начисляется **2** стихии поверженного босса (в `onConfirmVictory`); для боссов без стихии («Пробуждённый») стихия не начисляется.
- **Предзаполнение пролога**: при старте новой кампании (`onStartCampaign` → `startBattleInternal`, `isPrologue = true`) в меню подготовки автоматически выбран босс **Вираксен** сложности **0** (поля dfw/hsc заполняются из первой стойки Вираксена сложности 0). Для последующих боёв кампании предзаполнение не применяется.
- **Идемпотентность заданий**: `quests` имеет уникальный индекс `(campaign_id, quest_id)` (миграция 8→9 чистит существующие дубликаты); `saveQuest` — апсерт (`ON CONFLICT(campaign_id, quest_id) DO UPDATE`), повторные нажатия «Продолжить»/«К листу кампании» не создают дубликатов.
- **Начисление ресурсов реальным охотникам**: после создания кампании (`onStartCampaign`) в `state.hunters` кладутся охотники с реальными id из БД (перечитываются через `getHunters(campaignId)`), а не с `id = 0`. Пост-победные ресурсы начисляются по этим id.
- **Защита от двойного сохранения**: `onConfirmVictory`/`onQuestRewardsAccept` блокируют повторный вызов (`isSaving`), кнопки «Продолжить»/«Принять» неактивны на время сохранения; после успешного сохранения закрывается текущий диалог и открывается окно наград главы (`showChapterRewards`), а переход на лист кампании происходит после «Принять»/«Отклонить» в нём.
- **Автосохранение** при победе/поражении/каждом раунде
- **Флоу заданий**: перед боем выбирается активное задание из открытых (диалог «Выбор задания»); при победе оно завершается. После победы вводятся открывшиеся задания (чекбоксы) и ресурсы. После поражения вводится открывшееся задание (чекбоксы), которое становится доступным.
- **Список заданий в листе кампании**: показываются только **открытые** задания (`isAvailable = true`), отсортированные по возрастанию `questNumber`. Для каждого задания отображается название и босс (стихия + имя) из каталога `TaskInfo` (например, «Память пустыни — Торамат (Рог)»); при отсутствии данных каталога — «Задание N». То же отображение применяется в диалоге выбора активного задания перед боем (`QuestSelectDialog`). Кнопка «Выполнено» помечает открытое задание выполненным **и открывает зависимые задания** из каталога `TaskInfo` (безусловный список `victoryOpenQuests` + условные правила `victoryOpenQuestConditions` с учётом текущей главы и достижений — например, после задания 1 в главах 1–2 открывается задание 4, иначе 6). Материи/растения/достижения при ручном «Выполнено» не начисляются (только открытие заданий; решение qa 70).
- **Достижения в листе кампании**: секция «Достижения» показывает полученные достижения (зелёным) и кнопку «Редактировать». Диалог редактирования позволяет **добавить** достижение (свободный ввод названия) или **удалить** имеющееся. Достижения выдаются за победы (`TaskInfo.victoryAchievements`), решения глав и вручную; все считаются «полученными» (`unlocked = true`). Удаление достижения — DAO `deleteAchievement(campaign_id, achievement_id)`.
- **Окно наград за задание** (`QuestRewardsDialog`): после победы/поражения в бою кампании (**кроме пролога**) показывается окно с наградами активного задания из каталога `TaskInfo` (материи, растения, открываемые задания, достижения, карты наград, особые награды; при поражении — открываемые задания). Кнопки:
  - «Принять» — автоматически применяет награды: начисляет материи/растения всем охотникам, 2 стихии босса, выдает достижения, открывает задания, завершает активное задание, сохраняет трофей, переходит на лист кампании.
  - «Редактировать» — для победы открывает `PostVictoryDialog`, предзаполненный данными каталога (босс, стихия, материи, растения, задания); для поражения — форму с чекбоксами номеров заданий (сохранение через `onBattleFinished`).
  - «Выход» — закрывает окно без применения.
- Для пролога окно наград задания не показывается (сразу переход к награде за главу, см. 31.6).
- **Флаг окна наград**: `CampaignUiState.showQuestRewards` + `questRewardsMode` (VICTORY/DEFEAT) + `activeQuestNumber`; награды берутся из `taskInfoByQuestNumber`.
- **Окно наград за главу** (`ChapterRewardsDialog`): после победы и утверждения наград задания (в прологе — сразу после победы) показывается окно с наградами/эффектами главы из `ChapterInfo`. Кнопки:
  - «Принять» — применяет эффекты главы: начисляет ресурсы главы всем охотникам, открывает задания (`openQuests` + условные по достижениям), помечает истёкшие недоступными (`expireQuests`), повышает уровни кузни/лаборатории при флагах (`updateForgeLevel`/`updateLabLevel`), переходит к следующей главе (`updateChapter(currentChapter + 1)`) и открывает лист кампании.
  - «Отклонить» — не применяет эффекты главы и не меняет главу; переход к листу кампании.
  - Интерактивные решения (`ChapterDecision`, гл.7 «Тренироваться у подножья Волтьяра» Да/Нет) — кнопки выбора; при выборе варианта `optionForAchievement` выдаётся достижение `achievementOnOption`.
  - Условные сообщения (`conditionalMessages`) показываются при наличии соответствующего достижения.
- **Переход глав**: `saveVictory` больше не вызывает `advanceChapter`; переход к следующей главе происходит при «Принять» наград главы (глава += 1). Ручное изменение главы доступно на листе кампании (`onUpdateChapter`).
- **Режим экспедиции**: быстрый бой без кампании. BattleViewModel сохраняется в CampaignViewModel, состояние боя не теряется при выходе в меню и возврате.
- **Pre-battle диалог**: выбор босса из БД (дедупликация по имени + «Ввести данные вручную»), выбор сложности (0-3). Список боссов сортируется: «Ввести данные вручную» первым, затем боссы по алфавиту (сначала стихия по русскому названию, затем имя), «Пробуждённый» последним. Для кампании сложность предзаполняется по главе: 1→0, 2-4→1, 5-8→2, 9-11→3. При выборе босса/сложности поля dfw/hsc автозаполняются из первой стойки выбранной сложности. При выборе босса в кампании после победы поля «стихия» и «название босса» предзаполняются.
- **База боссов**: `BossEntity` — название, стихия (nullable), сложность, до 5 стоек с damageForWound (nullable) и healthForStanceChange. Боссы: Вираксен (Огонь), Иекорос (Молния, смена по запросу), Пробуждённый (без стихии, только сложность 3, 5 стоек), Торамат (Рог), Юром (Металл), Озев (Молния), Моркраас (Кристалл), Дигоракс (Рог), Харджа (Огонь), Коровон (Коралл, стойка II без порога раны), Таррагуа (Металл), Фелаксир (Кристалл), Оруксен (Коралл), Пазис (Перо), Нагарджас (Перо), Зекалит (Молния), Зекат (Молния), Тараск (Огонь), Кситерос (Перо, Ст2 — смена по запросу). Seed выполняется и при миграции (7→8), и при создании БД (`onCreate`-колбэк) — на чистой установке список боссов заполнен. `seedBosses` заполняет стойки 4–5 значением 0, а `BossEntity.stance4Dfw/stance5Dfw` имеют `@ColumnInfo(defaultValue = "0")` — Room-схема совпадает с `CREATE_BOSSES_TABLE`, onCreate-seed не падает с `NOT NULL constraint failed: bosses.stance4_dfw`.
- **Каталог заданий**: `TaskInfoEntity` (таблица `task_info`, миграции 9→10, 10→11, 11→12) — статический справочник по 40 заданиям из `doc/taskInfo.md`: номер, название, босс (имя + стихия), награды за победу (материи, растения, открываемые задания, достижения, карты наград, особые награды) и награды за поражение (открываемые задания). Мапы/списки хранятся текстом (`NAME:qty` через `;`, списки номеров через `,`). Seed выполняется при миграции и при создании БД (`onCreate`). Условные правила (`TaskCondition`) хранятся в колонках `victory_open_quest_conditions`/`defeat_open_quest_conditions` текстом: `kind|achievement|chapterSet|quest|else|rewardAchievement`, условия разделяются `;`. Виды условий: `CHAPTER_IN`, `ACHIEVEMENT_OWNED`, `ACHIEVEMENT_NOT_OWNED`; комбинированное «достижение И глава» — `ACHIEVEMENT_OWNED_IN_CHAPTER` (зад. 25); условные достижения (выдача достижения при наличии другого, зад. 29/40) — поле `rewardAchievement`. При применении условий открывается **первое** условие, давшее целевое задание (зад. 25: при главе 8 задание 34 вместо 27). Доступ через репозиторий: `getAllTaskInfo()` / `getTaskInfo(questNumber)`.
- **Каталог глав**: `ChapterInfoEntity` (таблица `chapter_info`, миграция 10→11) — справочник по 11 главам из `doc/compainInfo.md`: награды (материи/растения), открываемые и истекающие задания (в т.ч. условные по достижениям), повышение уровней кузни/лаборатории, «улучшение набора охотника» (флаг), интерактивные решения (`ChapterDecision`), сообщения. Ссылки на задания 41/46 оставлены как в источнике. Доступ через репозиторий: `getAllChapterInfo()` / `getChapterInfo(chapter)`.
- **Стойка без порога раны** (`damageForWound = null`): на такой стойке урон только накапливается в `accumulatedDamage`, раны не наносятся и босс не может быть побеждён. При подтверждении смены со стойки без порога на стойку с порогом весь накопленный урон немедленно пересчитывается в раны по прочности новой стойки (например, Коровон: стойка II накапливает урон, при переходе на стойку III урон наносится). Поле «урон для нанесения раны» в pre-battle и в меню смены стойки можно оставить пустым — стойка будет без порога раны (урон накапливается).
- **Смена стойки**: при переходе на новую стойку поля диалога предзаполняются данными из `selectedBoss.stances[currentPhase]`.
- **Боссы с ручной сменой стойки**: `healthForStanceChange = null` — стойка меняется по запросу (кнопка «Сменить стойку», активна при null). Иекорос (Молния) — все стойки с null. В окне «Подготовка к бою» поле «Здоровье для смены стойки» не предзаполняется для таких боссов. При ручном вводе пустое поле hsc допускает старт боя (смена по кнопке).
- **Кнопка «Сдаться»**: в бою с диалогом подтверждения, переход в DEFEAT.
- **Сохранение состояния при повороте**: `android:configChanges` в манифесте предотвращает пересоздание Activity при повороте экрана. Бой не сбрасывается при смене ориентации.
- **Устойчивость к ошибкам БД**: `fallbackToDestructiveMigration(true)` на обеих платформах. Миграции: `1→2` (колонка `quest_number`), `2→3`/`3→4`/`4→5` (боссы, `element` nullable, «Пробуждённый»), `5→6`/`6→7`/`7→8` (пересоздание боссов + seed, `dfw` nullable), `8→9` (уникальный индекс `quests(campaign_id, quest_id)`), `9→10` (таблица `task_info`), `10→11` (колонки условий в `task_info` + таблица `chapter_info`), `11→12` (пере-сид `task_info` с расширенной моделью условий — составное условие зад. 25, условные достижения зад. 29/40).
- **Возврат к активному бою**: при выходе из незавершённого боя (PRE_BATTLE или PHASE_I–IX) в главное меню появляется кнопка «Вернуться к бою». Нажатие восстанавливает экран боя с сохранённым состоянием. При завершении боя (VICTORY/DEFEAT) кнопка не появляется.
  - `CampaignUiState.lastActiveBattle: AppScreen?` — сохраняет экран боя при выходе из активной фазы
  - `CampaignViewModel.onPauseBattle()` — сохраняет текущий экран в `lastActiveBattle`, переводит в `MainMenu`, не уничтожает BattleViewModel
  - `CampaignViewModel.onResumeBattle()` — восстанавливает экран из `lastActiveBattle`

Реализовано в:
- `shared/.../database/` — Room KMP (9 Entity, 9 DAO, mapper, repository impl, platform expect/actual)
- `shared/.../viewmodel/CampaignViewModel.kt` — управление состоянием кампании
- `shared/.../domain/` — валидаторы навыков, обмена, прогрессии глав
