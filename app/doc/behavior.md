# Primal App — Описание поведения приложения

## Общая концепция

Primal App — мобильное приложение-компаньон для настольной кооперативной игры «Primal. Пробуждение». Приложение автоматизирует учёт здоровья монстра, накопленного урона, ярости, фаз боя и смены стоек.

С версии 1.3 приложение повторяет функции сайта (`web/`), кроме администрирования: кампании с кузницей,
лабораторией, инвентарём, обменом, историей боёв и переходами глав по правилам каталога, «Инфо», вход в аккаунт,
совместная игра по ссылке. Работает **онлайн** (справочники и кампании аккаунта синхронизируются с сервером, по
умолчанию `https://primalhelper.ru/`) и **офлайн** (всё на устройстве) — `doc/sync.md`.

**Платформа:** Kotlin Multiplatform (Android + iOS).

**Состояние приложения управляется конечным автоматом** из состояний `FightPhase`:
`PRE_BATTLE`, `SETUP`, `PHASE_I`…`PHASE_IX`, `VICTORY`, `DEFEAT`.

```
                    ┌─────────────┐
                    │  PRE_BATTLE │──── Начало боя ────┐
                    └─────────────┘                    │
                           ▲                           ▼
                           │                    ┌──────────┐
                           │                    │ PHASE_I  │
                           │                    └────┬─────┘
                           │               ┌─────────┼──────────┐
                           │               │  нанесён урон       │
                           │               ▼                     ▼
                           │        ┌──────────┐          ┌──────────┐
                           │        │ PHASE_II │          │  DEFEAT  │ ← раунды истекли
                           │        └────┬─────┘          └──────────┘
                           │    ┌────────┼────────┐
                           │    │ нанесён урон      │
                           │    ▼                   ▼
                           │ ┌──────────┐    ┌──────────┐
                           │ │PHASE_III │    │  DEFEAT  │
                           │ └────┬─────┘    └──────────┘
                           │      │ … (цепочка до PHASE_IX)
                           │      ▼
                           │ ┌──────────┐
                           └─│ VICTORY  │
                             └──────────┘
```

**Поток данных:** `Monster + Hunter (модели)` → `BattleViewModel (MVVM)` → `StateFlow<BattleScreenState>` → `MainActivity (Compose UI)`

**Кампании:** действие игрока → ViewModel экрана → `CampaignStore.perform(CampaignOp)` → `CampaignRules` (правила) →
документ кампании в Room → `Flow` → экран; онлайн — `SyncEngine` отправляет изменения на сервер.

## 1. Главное меню и экран «Подготовка к бою»

**Главное меню** (`ui/MainMenuScreen.kt`): «Режим экспедиции», «Режим кампании», «Инфо», «Вернуться к бою» (если
бой идёт или закончен, но итог кампании не принят), строка состояния связи («Онлайн · Алиса», «Онлайн · вход не
выполнен», «Нет связи с сервером», «Офлайн-режим») и «Настройки».

**Подготовка к бою** — одна форма для экспедиции и боя кампании (`ui/BattleSetupScreen.kt`,
`viewmodel/BattleSetupViewModel.kt`). Боссы, стойки и уровни враждебности — из каталога (раздел 10 и
`doc/sync.md` §2): с сервера или из файла приложения.

| Поле | По умолчанию | Описание |
|------|-------------|----------|
| Босс | «Ввести данные вручную» (кампания — босс задания) | «Огонь - Вираксен»: выбор заполняет поля ниже стойкой I уровня враждебности |
| Сложность | `0` (кампания — по главе: пролог 0, главы 1–3 → 1, 4–7 → 2, 8–11 → 3) | Доступны уровни выбранного босса; нет текущего — единственный доступный (Пробуждённый — 3) |
| Колода реакций | — | «Подготовьте колоду карт реакций:» и картинка уровня |
| Количество охотников | `4` (кампания — размер отряда, не меняется) | Целое > 0 |
| Урон для нанесения раны на игрока | из стойки I | Пусто — нет порога раны. Фактическая прочность = `hunterCount × damageForWound` |
| Здоровье для смены стойки | из стойки I | Пусто — по запросу, `0` — последняя стойка |

**«Начать бой»** проверяет поля. В кампании: если другие участники ведут бой (отметки «Идёт бой» на сервере) —
окно «Уже идёт бой» со списком и объяснением, что главу засчитывает первая принятая победа; если в приложении уже
есть незаконченный бой — «Текущий бой будет потерян. Начать новый бой?» (заменённый бой кампании отмечается
брошенным). «Другое задание» — назад к выбору задания, «Выход в меню».

## 2. Экран «Battle» — Боевой экран

**Файл:** `MainActivity.kt:158–306` — функция `BattleScreen`

Отображается при состояниях `PHASE_I`…`PHASE_IX`.

### 2.1 Информационная панель

В верхней части экрана:
- **Текущая фаза** (I…IX) и раунд (N / 10)
- **Здоровье монстра** и текущая **ярость**
- **Накопленный урон** и **прочность** (урон для раны)
- **Статус** («Затвердевший», «Устойчивость стойки», оба через запятую или «Обычный») и **порог смены стойки**
- **Подсветка изменённых параметров (задача 37.1):** после изменения любого параметра (фаза, раунд, здоровье, ярость, накопленный урон, прочность, статус, смена стойки) значение отображается красным (`MaterialTheme.colorScheme.error`) и жирным в течение **1 секунды**, затем возвращается к обычному виду (`BattleScreenState.highlightedParams`, авто-сброс в `BattleViewModel` через `delay(1000)`; повторное изменение продлевает подсветку).
- **Вибрация (задача 37.2):** короткий отклик при нажатии кнопок/управлений и при применении урона (в т.ч. авточерез 2 с после быстрой кнопки); **двойной** отклик при нанесении раны (`woundsInflicted > 0`, заменяет короткий). Ввод символов в поле «Ввести урон» не вибрирует. Android: `Vibrator` + разрешение `VIBRATE`; события эмитятся в `BattleViewModel.vibrationEvents` (`SHORT`/`DOUBLE`).

### 2.2 Нанесение урона

Нанесение урона управляется конечным автоматом режимов ввода (`InputMode`):

```
                    нажатие (+N)
     ┌──── NONE ──────────────────► QUICK_BUTTON ─────┐
     │                                  │   таймер 2с  │
     │  OK / Cancel                клик в поле         │
     │                                  │   (сброс     │
     │                                  ▼   таймера)   │
     ├──────── MANUAL ◄─────────────────┘              │
     │            │                                    │
     │      нажатие (+N)                               │
     │      (накопление,                               │
     │       без таймера)                              │
     │            │                                    │
     └────────────┴── Enter / OK ──► commitDamage() ───┘
```

#### Режимы ввода (`InputMode`)

| Режим | Описание | Таймер |
|-------|----------|--------|
| `NONE` | Начальное состояние, нет активного ввода | Нет |
| `MANUAL` | Пользователь печатает в поле ввода | Нет |
| `QUICK_BUTTON` | Нажаты кнопки (+1/+5/+10/+50) | 2 секунды |

#### Кнопки быстрого добавления

| Кнопка | Значение | Метод ViewModel |
|--------|----------|-----------------|
| +1 | 1 | `onQuickButtonPress(1)` |
| +5 | 5 | `onQuickButtonPress(5)` |
| +10 | 10 | `onQuickButtonPress(10)` |
| +50 | 50 | `onQuickButtonPress(50)` |

**Поведение кнопок (+1/+5/+10/+50):**

1. **Если режим `NONE` или `QUICK_BUTTON`:** значение накапливается (`pendingDamage += amount`), таймер 2с запускается или сбрасывается. Поле ввода обновляется.
2. **Если режим `MANUAL` (пользователь уже печатал):** значение накапливается, но таймер **не запускается**. Поле ввода обновляется.
3. **Таймер 2 секунды:** если в течение 2 секунд не нажата ни одна кнопка, урон применяется автоматически (`commitDamage()`).
4. **Кнопка «Применить урон сейчас (N)»:** отображается при активном таймере для немедленного применения.

#### Ручной ввод урона

- **Поле ввода** (`OutlinedTextField`) управляется ViewModel через `state.damageInputText`.
- При вводе с клавиатуры режим переключается в `MANUAL`, таймер отменяется.
- **Клавиша Enter** на клавиатуре или кнопка **OK** — мгновенное применение урона.
- **Кнопка «Отмена»** — сброс `pendingDamage` в 0, очистка поля, возврат в `NONE`.

#### Заживление раны и отрицательный урон

- Кнопка **«Заживить рану (+1 здоровья)»** (`BattleViewModel.healWound()` → `Monster.healWound()`): +1 здоровья по правилу «заживить рану», жетоны урона (`accumulatedDamage`) не меняются. Здоровье не поднимается выше начального (10); у побеждённого монстра не действует. Действие отменяется «Отменить действие» (`ActionType.HEAL`) (defects.md R-4).
- **Отрицательный урон** в поле ввода уменьшает только накопленный урон: `accumulatedDamage -= min(|amount|, accumulatedDamage)`. Здоровье не меняется; при `accumulatedDamage = 0` ввод ничего не делает — сообщение «Накопленного урона нет.» (D-3). Под полем «Ввести урон» выводится подсказка «Отрицательное значение отменяет накопленный урон». Клавиатура поля — `KeyboardType.Decimal`, знак минуса доступен.

#### Смешанные сценарии

| Сценарий | Поведение |
|----------|-----------|
| Кнопки (+N) → клик в поле ввода | Таймер останавливается, урон только по OK/Enter |
| Ручной ввод → кнопки (+N) | Число меняется, таймер не запускается |
| После Отмена / OK | Возврат в `NONE`, таймер запустится при следующем (+N) |

#### Применение урона

**Файл:** `BattleViewModel.kt` — метод `commitDamage`

Вызывает `Monster.takeDamage(pendingDamage)`. Перед применением сохраняет снимок состояния монстра (`MonsterSnapshot`) для возможной отмены.

#### Отмена последнего действия

**Файл:** `BattleViewModel.kt` — метод `onUndoPress`

Кнопка **«Отменить действие»** отображается после каждого мутирующего действия (`canUndo = true`). Поддерживается **до 10 отмен** подряд. Восстанавливает полное состояние монстра (здоровье, фазу, накопленный урон, ярость, прочность, порог стойки), `FightPhase` и **номер раунда** (`ActionSnapshot.round`, D-4) на момент перед последним действием. Отмена урона, вызвавшего автоматическую смену стойки по данным из базы боссов, возвращает и прежнюю стойку.

**Действия, которые можно отменить:**
- Нанесение урона и отрицательный урон (`DAMAGE`)
- Заживление раны (`HEAL`)
- Изменение ярости через кнопки ±1, +1/охот, +1/охот-1 (`RAGE`)
- Смена стойки через диалог или кнопку «Сменить стойку» (`PHASE_CHANGE`)
- Завершение раунда (`ROUND_END`) — раунд возвращается к прежнему номеру

**Реализация:** стек `actionHistory: MutableList<ActionSnapshot>` (max 10). Снимок сохраняется перед каждым действием через `saveSnapshot()`. При отмене:
1. Извлекается последний `ActionSnapshot`
2. Восстанавливаются поля `Monster` (health, accumDamage, phase, rage, isDefeated)
3. Восстанавливается `FightPhase`
4. `canUndo = actionHistory.isNotEmpty()`

Алгоритм `Monster.takeDamage` (файл: `MonsterExt.kt`):
1. Отрицательное значение — уменьшение накопленного урона (см. выше), раны не наносятся.
2. `accumulatedDamage += amount`
3. **Цикл ран:** пока `accumulatedDamage >= damageForWound`:
   - `accumulatedDamage -= damageForWound`
   - `currentHealth -= 1`
   - Если `currentHealth <= 0` → `isDefeated = true`, возврат
   - Если `currentHealth <= healthForStanceChange` и не последняя фаза → `currentPhase++`, **цикл останавливается**: оставшийся урон переносится на новую стойку и наносится уже с её прочностью (правила, стр. 1440–1493; defects.md R-2)
4. **После цикла:** если «Затвердевший» и были раны → `accumulatedDamage = 0` (остаток сгорает). Иначе остаток сохраняется

**Смена стойки после урона** (`BattleViewModel.applyDamage`, используется в `commitDamage`, `endRound`, `confirmPhaseChange`):
- при каждой смене стойки открывается диалог «Смена стойки!» (§3); перенесённый урон ждёт подтверждения параметров новой стойки;
- если стойка известна из базы боссов (`selectedBoss.getStance(phase − 1)`), поля диалога заполнены её значениями, их можно исправить (`BattleScreenState.phaseChangeFromBossData = true`); иначе поля пустые;
- победа определяется двумя проверками: `monster.isDefeated` **или** сообщение «побеждён» (D-18).

Пример книги: вираксен (прочность 4, порог 7, здоровье 9), 13 урона → 2 раны, 5 урона переносится на стойку II (прочность 6) — третьей раны нет.

### 2.3 Управление яростью

**Файл:** `BattleViewModel.kt:159–199`

В начале боя монстр получает **ярость, равную числу охотников** (`startBattleWithHunters` → `rage = hunters.size`; задача 35.2).

| Кнопка | Метод | Поведение |
|--------|-------|-----------|
| -1 | `removeRage(1)` | `rage = max(rage - 1, 0)` |
| +1 | `addRage(1)` | `rage += 1` |
| +1/охот | `addRagePerHunter()` | `rage += hunterCount` |
| +1/охот-1 | `addRagePerHunterMinusOne()` | `rage += max(hunterCount - 1, 0)` |

### 2.4 Статусы «Затвердевший» и «Устойчивость стойки»

Два независимых переключателя (defects.md R-3), у каждого — кнопка **«i»** в сером кружке, открывающая описание статуса (`MonsterStatusInfo`, `BattleViewModel.onStatusInfoRequested/onStatusInfoDismissed`, диалог с кнопкой «Понятно»):

| Статус | Метод | Поле | Действие |
|--------|-------|------|----------|
| «Затвердевший» (состояние монстра, например торамат и дигоракс) | `toggleHardened()` | `Monster.isHardened` | После нанесения ран остаток урона **сгорает** (`takeDamage`) |
| «Устойчивость стойки» (ключевое слово карты стойки) | `toggleResilient()` | `Monster.isResilient` | При смене стойки накопленный урон **не переносится** на новую стойку (`resetPhase` обнуляет `accumulatedDamage`) |

### 2.5 Выплеск ярости

**Файл:** `BattleViewModel.kt` — метод `confirmRageSurge`, поле `showRageSurgeDialog`

При каждом изменении ярости (кнопки +1/-1/+охот, завершение раунда, отмена действия) проверяется условие:
```
rage >= hunterCount * 3
```

При срабатывании:
- Отображается диалог **«Выплеск ярости»** (термин правил): «Ярость монстра достигла 3 за каждого охотника. Каждый охотник получает урон, равный силе монстра. После этого ярость сбрасывается до 1 за каждого охотника» (defects.md R-8)
- Кнопка **OK** вызывает `confirmRageSurge()` — ярость сбрасывается до `hunterCount`, сообщение «Выплеск ярости! Каждый охотник получил урон, равный силе монстра. Ярость сброшена до N»

### 2.6 Выход в главное меню

Кнопка **«Выход в меню»** на боевом экране оставляет бой в приложении — в главном меню появляется «Вернуться к бою».
Экраны итога — раздел 4. Кнопка **«Инфо»** под ней открывает справку (раздел 12) и возвращает в бой.

### 2.7 Завершение раунда

**Файл:** `BattleViewModel.kt` — метод `endRound`

Кнопка **«Закончить раунд»**:
1. Если есть накопленный, но не применённый урон (`pendingDamage > 0`):
   - Вызывает `Monster.takeDamage(pendingDamage)`, получает `DamageResult`
   - Если босс **побеждён** → `phase = VICTORY`, досрочный выход (раунд не завершается)
   - Если **смена стойки** → обновляется `FightPhase`, открывается диалог «Смена стойки!» (поля — из базы боссов, если стойка известна)
2. Вызывает `Monster.endRound(hunterCount)` — добавляет +1 ярости за каждого охотника
3. `currentRound += 1`
4. Если `currentRound > maxRounds (10)` → `phase = DEFEAT` (поражение)
5. Иначе продолжается текущая фаза, проверяется всплеск ярости

### 2.8 Завершить бой

**Файлы:** `ui/BattleScreen.kt` (окно), `BattleViewModel.kt` — `finishWithVictory`, `onSurrender`

Кнопка **«Завершить бой»** (раньше — «Сдаться») открывает окно «Завершить бой»: «Как закончился бой? «Завершить
победой» — монстр повержен; «Сдаться» — бой засчитывается как поражение.»

| Кнопка | Метод | Итог |
|--------|-------|------|
| «Завершить победой» | `finishWithVictory()` | `phase = VICTORY` — «ПОБЕДА! Монстр повержен!» (бой закончился по правилам игры, а урон не вносили до конца) |
| «Сдаться» | `onSurrender()` | `phase = DEFEAT`, `surrendered = true` — «ПОРАЖЕНИЕ», «Вы сдались.» (D-14) |
| «Отмена» | — | окно закрывается, бой продолжается |

Оба итога можно отменить («Отменить итог» — снимок `ActionType.FINISH`): бой возвращается к состоянию до нажатия.
В бою кампании дальше — как при обычной победе или поражении (раздел 8).

## 3. Смена стойки — диалог PhaseChangeDialog

**Файл:** `MainActivity.kt:308–352`

Отображается при `state.showPhaseChangeDialog == true` (модальное окно `AlertDialog`) при каждой смене стойки — по порогу здоровья или по кнопке «Сменить стойку».

Информация в окне:
- «Монстр перешёл на стойку N.»
- откуда значения: «Параметры заполнены из базы боссов — при необходимости исправьте:» (стойка есть у выбранного босса; значения — `BattleScreenState.pendingDamageForWound`/`pendingHealthForStanceChange` из `selectedBoss.getStance(N − 1)`) или «Данных о стойке в базе боссов нет — укажите параметры:» (ручные данные или стойка за пределами карт босса — поля пустые);
- если есть перенесённый урон: «Перенесённый урон K будет нанесён с новой прочностью после «OK».», а при «Устойчивости стойки» — «Перенесённый урон K сбросится («Устойчивость стойки»)».

Три поля:
- **Урон для нанесения раны на игрока** — новый `damageForWound` (на игрока, умножается на `hunterCount`)
- **Здоровье для смены стойки** — новый порог. Если `> 0`, появляется третье поле. Если `0` или пусто — последняя стойка (дальнейшая смена не происходит).
- **Здоровье босса в новой стойке** — опционально, начальное HP для новой фазы

Кнопка **OK** вызывает `viewModel.confirmPhaseChange(wound, stance, bossHealth)`:
- `Monster.resetPhase(damageForWound, healthForStanceChange)` — обновляются пороги; `accumulatedDamage` переносится на новую стойку, обнуляется только при «Устойчивости стойки»
- Если `bossHealth > 0`, устанавливается `currentHealth = bossHealth`
- Перенесённый урон сразу наносится с новой прочностью (R-2); если он снова доводит до порога, окно сразу показывает следующую стойку (номер, перенесённый урон и поля обновляются)
- Диалог закрывается. При следующем достижении порога смены стойки диалог появится снова — до 9 стоек.

Кнопка **Отмена** вызывает `viewModel.dismissPhaseChangeDialog()`:
- Откатывает урон, вызвавший смену стойки (через `onUndoPress()`)
- Восстанавливает состояние монстра к моменту перед уроном
- Закрывает диалог (`showPhaseChangeDialog = false`)

## 7. Кампании

Правила кампании — те же, что на сайте (`web/doc/behavior.md` §6–10); приложение выполняет их само, поэтому
кампании работают и без сети. Синхронизация с сервером — `doc/sync.md`. Нумерация глав — книжная: «Пролог»
(глава 0), главы 1–11 (до версии 1.3 приложение показывало главу книги + 1; миграция 17→18 переводит кампании).

### 7.1 Список (`ui/CampaignListScreen.kt`)

- «Новая кампания»; кампании — недавно изменённые сверху: название, глава («Пролог», «Глава N», «Ждёт перехода
  главы», «Пройдена»), отряд «Класс — игрок», где кампания: «Только на устройстве», «На сервере», «По ссылке ·
  владелец …»; «Есть изменения, не отправленные на сервер»; сообщение синхронизации.
- «Загрузить на сервер» — у кампаний «только на устройстве», если выполнен вход; «Удалить» — с подтверждением (своя
  на сервере удаляется и у всех участников; кампанию по ссылке удалить нельзя).

### 7.2 Создание (`ui/CampaignCreateScreen.kt`)

Название и отряд из 2–5 охотников (8 классов; порядок выбора — порядок в отряде, номер виден рядом с классом), имя
игрока для каждого (пусто — название класса). Каждый охотник получает стартовые предметы: основное оружие класса,
«Основной шлем», «Основной доспех» (1-й уровень) и зелье «Алемор». После входа в аккаунт кампания будет загружена
на сервер. После создания сразу открывается подготовка пролога: Вираксен, сложность 0.

### 7.3 Лист кампании (`ui/CampaignSheetScreen.kt`, `viewmodel/CampaignSheetViewModel.kt`)

**Шапка:** глава и «Изменить главу» (0–11, исправление ошибки: бои, начатые раньше, не принимаются; недоступно, пока
глава ждёт перехода), «Кузня: N · Лаборатория: N · Уровень враждебности: N», финальный бой главы 11, где кампания
(«На сервере», «По ссылке · владелец …», «Только на устройстве»), «Обновить» (онлайн-кампания).

**Бой:** баннеры «Идёт бой: Вадим, задание 1 «…», с 18:30»; «Начать бой» (пролог и финал — сразу подготовка, иначе
— выбор задания: открытые задания с боссом и стихией, пометка дополнения, «Продолжить без задания»), «Переход
главы», если глава ждёт перехода, или «Кампания пройдена! Пробуждённый повержен.». Ниже — «Кузница»,
«Лаборатория», «Инфо», «Поделиться» и «Ссылка на сайт» — у любой кампании, со входом и без:

| Кнопка | Без входа | Вход выполнен |
|--------|-----------|---------------|
| «Поделиться» | окно «Вход в аккаунт»: «Чтобы поделиться кампанией, войдите в аккаунт.» — «Войти» (экран входа) / «Отмена» | своя кампания на сервере — окно ссылки-приглашения (раздел 11); кампания только на устройстве — «Загрузить её на сервер, чтобы поделиться?» → «Загрузить»; по ссылке — «Ссылкой-приглашением управляет владелец…»; офлайн — «Поделиться можно в онлайн-режиме…» |
| «Ссылка на сайт» | кампания на сервере — ссылка `<сервер>/campaigns/<id>` (системное окно «Поделиться»); только на устройстве — «Ссылка на сайт появится, когда кампания будет на сервере…» → «Войти» | на сервере — ссылка; только на устройстве — «Загрузить её на сервер, чтобы получить ссылку на сайт?» |

Своя кампания на сервере, оставшаяся после выхода из аккаунта, — «Кампания на сервере · вход не выполнен: изменения
уйдут на сервер после входа в её аккаунт».

**Вкладки:**

| Вкладка | Что там |
|---------|---------|
| Охотники | Выбор охотника, «Изменить имя игрока»; древо навыков А–Д × 2 ступени (ступень 2 — после ступени 1, ступень 1 не снимается при открытой 2); материи, растения, стихии с иконками и −/+ (минимум 0); «Обменять ресурсы»; инвентарь: «Снаряжение», «Зелья», «Карты наград» с уровнем, ✎ — название и уровень, × — убрать, «Добавить предмет» (без оплаты) |
| Задания | «Открытые» с «Выполнено» (открывает задания из наград победы без ресурсов и достижений; окно «Задание выполнено» с условными заданиями); «Выполненные:» с «Отмена» (снова открыто, открытые им задания не меняются); «Истёкшие:»; «Редактировать задания» (выполненные и истёкшие недоступны) |
| Достижения | Список (своё — «(своё)»), «Удалить»; добавление с подсказками из каталога — написание приводится к каталогу, равнозначное достижение заменяется |
| Трофеи | Побеждённые боссы и главы побед |
| История | Бои: итог, задание, глава, «начало: кто, когда», «итог: кто, когда», статус (идёт, принят, отклонён, брошен); у идущего — «Снять отметку» |
| Заметки | Сохраняются сами через 0,8 с после последнего изменения («Сохраняю…», «Сохранено») |

Задания отключённых в настройках дополнений не показываются (в кампании они остаются).

### 7.4 Кузница (`ui/WorkshopScreens.kt` → `ForgeScreen`)

«Кузня: N», выбор охотника. Открытые кузни — стихии побеждённых боссов (трофеи); пока их нет — «Кузни ещё не
открыты…». «Запас:» — стихии и материи охотника. Планшет стихии текущего уровня: оружие класса выбранного охотника
(чужое оружие не показывается), шлем, доспех, 2 предмета; цена иконками — 1 стихия кузни и материи планшета.
«Создать» недоступна при нехватке («Не хватает: Кровь 1» и «Обменять ресурсы» с недостающим). Окно «Создать
снаряжение?» — «Будет списано: Огонь 1, Кости 1, Кровь 1.»; после — «Язык пламени» создан — возьмите из коробки
карту 1-го уровня.», карта в инвентаре со стихией кузни.

### 7.5 Лаборатория (`LabScreen`)

«Лаборатория: N», выбор охотника, «Запас:» — растения, «Цены одинаковы на всех уровнях…». 6 зелий: цена «1 Антемон»,
«1 Тармарет / Альбалацея», «1 любое растение». «Приготовить» — окно с выбором растения там, где выбор или «любое»
(«Антемон (1)»; по умолчанию — первое по планшету сочетание, на которое хватает запаса), «Будет списано: …» или «На
выбранные растения запаса не хватает — выберите другие.». Не хватает растений — «Обменять ресурсы» (сразу обмен).

**Зелье каждого вида у охотника одно** (вид — код зелья лаборатории, а у добавленного вручную — название без учёта
регистра; `CampaignRules.existingPotion`). Окно «Приготовить» предупреждает заранее:
- зелья нет — «Зелье каждого вида у охотника одно: повторное приготовление повышает его уровень до уровня
  лаборатории.»; после — «Имперум» приготовлено — возьмите из коробки карту 1-го уровня.»;
- зелье ниже уровня лаборатории — «У охотника уже есть «Алемор» 1-го уровня: растения спишутся, зелье станет 2-го
  уровня.»; после — «Алемор»: уровень зелья повышен до 2-го — замените карту.»;
- зелье того же уровня (или выше) — «…растения спишутся, уровень зелья не изменится.»; после — «Алемор» приготовлено
  снова — уровень зелья остаётся 1-м.».

Растения списываются всегда; второе зелье не появляется. Добавить вручную («Добавить предмет», ✎) зелье, которое у
охотника уже есть, нельзя: «Зелье «Алемор» у охотника уже есть: зелье каждого вида одно — измените уровень
имеющегося.». Сайт работает так же (`web/doc/behavior.md`).

### 7.6 «Обменять ресурсы» (`ExchangeDialog`)

- **Обмен** 1 к 1 внутри типа: «Что хотите получить», «Что предлагаете взамен» (ресурс того же типа из запаса),
  «С кем обменяться» (у кого есть нужный ресурс); пояснения, если предложить нечего или ресурса нет ни у кого.
- **Преобразование**: «1 стихия → 1 материя» или «2 материи → 1 материя»; «Запаса не хватает.».
- **Продажа предмета**: карта снаряжения или награды (зелий нет) за 1 материю или 1 стихию кузни этой карты.

## 8. Итог боя кампании (`ui/ProgressionScreens.kt` → `OutcomeScreen`, `viewmodel/OutcomeViewModel`)

- Онлайн перед расчётом наград кампания обновляется с сервера.
- **Поражение**: окна наград нет — бой записывается в историю, лист кампании, «Поражение. Бой записан в историю.»
  (наград за поражение нет; последствия невыполненного задания — при истечении его времени, раздел 9).
- **Пролог**: победа принимается сама — трофей Вираксена и 2 «Огня» каждому, сразу переход в главу 1.
- **Награды за победу**: «Задание N «…» выполнено.», трофей, «Каждый охотник получает:» (стихии босса первыми,
  затем ресурсы задания), «Добавляются задания:», «Достижения:», сообщения, «Условные задания:» и «Условные
  награды:» — правило и результат для этой кампании; «Карты наград:» — «Кому выдать «Карту награды №7»» (по умолчанию
  первый охотник); предупреждение, если идут другие бои этой кампании.
- **Принять** — награды применяются, задание выполнено, глава ждёт перехода (финальный бой — «Кампания пройдена!
  Пробуждённый повержен.»), открывается переход главы.
- **Редактировать** — босс трофея (стихии меняются вместе с ним), ресурсы каждому охотнику, добавляемые задания,
  достижения; «Принять с правками» применяет ровно их.
- **Отклонить** — окно «Отклонить награды боя?» со списком того, что не будет применено; после подтверждения бой
  записывается в историю без наград.
- Бой без задания без выбранного босса — «Босс не выбран — укажите его через «Редактировать».».
- **Кампания изменилась** (главу закрыла чужая победа, сменилась глава, задание закрыто): причины и «Отклонить
  результат». Если это выяснилось уже при отправке на сервер — итог записывается отклонённым, игрок получает сообщение
  (`doc/sync.md` §5.3).

## 10. Настройки (`ui/SettingsScreen.kt`, `viewmodel/SettingsViewModel`)

- **Режим работы**: переключатель «Онлайн — с сервером» / «Офлайн — только устройство», состояние синхронизации,
  «Последняя синхронизация: …», откуда справочники («с сервера» / «встроенные в приложение»), «Синхронизировать».
- **Сервер**: «Адрес сервера» (по умолчанию `https://primalhelper.ru/`; без схемы — https), «Сохранить адрес»,
  «По умолчанию». Смена сервера — выход из аккаунта прежнего сервера (без подтверждения: кампании остаются на
  устройстве).
- **Аккаунт**: «Вход» / «Регистрация» (логин — латиница, цифры, «.», «_», «-», 3–32 символа; пароль 8–64; имя
  обязательно) — ошибки «Неверный логин или пароль.», «Логин … уже зарегистрирован. Войдите по нему.»; после входа —
  «Вы вошли как …», «Имя» и «Сохранить имя», «Выйти». Гостю по ссылке — пояснение и форма входа.
- **«Выйти»**: кампании остаются на устройстве (в том числе с неотправленными изменениями) — «Вы вышли из аккаунта.
  Кампании сохранены на устройстве.» (есть неотправленные — «…изменения уйдут на сервер после входа в этот
  аккаунт.»). В списке они помечены «На сервере · синхронизируется после входа в аккаунт» (по ссылке — «По ссылке ·
  …»), открываются и меняются; изменения уходят на сервер после входа в тот же аккаунт. Такую копию можно удалить с
  устройства: «Копия кампании «…» будет удалена с устройства; на сервере кампания останется.»
- **Экран «Вход в аккаунт»** (`Screen.Login`, `LoginScreen`) — из окон «Поделиться» и «Ссылка на сайт»: сервер,
  форма входа и регистрации, «Настройки сервера»; в офлайн-режиме — «Включить онлайн-режим». После входа — назад
  к листу кампании.
- **Дополнения**: «Кошмар» (31–35), «Перо» (36–40), «Яд» (41–45), «Лёд» (46–50) — у аккаунта сохраняются на
  сервере, без входа — в приложении.

## 12. Инфо (`ui/InfoScreen.kt`, `viewmodel/InfoViewModel`)

Открывается из главного меню, боя и листа кампании. Поиск по названию и тексту всех разделов («Название · Раздел»),
разделы с числом статей («скоро» у пустого). «Ключевые слова» — фильтр, статьи раскрываются нажатием (картинка и
текст); «Символы реакций монстров» и «Жетоны окружения» — карточки «картинка слева, текст справа». В тексте —
абзацы, **жирный**, в «(См. также «…» .)» названия — ссылки: статья раскрывается, список прокручивается к ней. Без
сети — последняя загруженная версия (картинки скачиваются заранее), до первой загрузки — версия из приложения.
